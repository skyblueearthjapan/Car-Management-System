## B. 予約仕様（業務ロジック）

### B-1. 時間枠（固定）

| スロット | 時間帯 |
|----------|--------|
| AM | 08:00–13:00 |
| PM | 13:00–18:00 |
| FULL | 08:00–18:00 |

### B-2. 予約の基本

- **複数日にまたがる予約を許可**
- デフォルトは「期間内すべて同一スロット」で一括作成

### B-3. 時間指定（任意・深い階層）

- 予約には `slot` を必ず持つ
- さらに任意で `start_time/end_time` を持てる（深い階層UIで設定）
- 時間指定がある場合：
  - AM は 08:00–13:00 内
  - PM は 13:00–18:00 内
  - FULL は 08:00–18:00 内

### B-4. 競合（重複）判定

同一 `vehicle_id`・同一 `date` で以下は不可：

| パターン | 判定 |
|----------|------|
| FULL vs AM/PM | **常に競合** |
| AM vs AM | **競合** |
| PM vs PM | **競合** |
| AM vs PM | **競合しない** |
| 時間指定あり | 時間帯の重なりで競合 |

> `start_time/end_time` が空の場合はそのスロット全体を占有とみなす

## E. マスタ同期仕様（既存DB→WebアプリDB）

### E-1. 同期元

| 項目 | 値 |
|------|-----|
| Spreadsheet ID | `1iu5HoaknlW1W1HheeYv0jqcRq-aY0SyEE2seQd2pHkQ` |
| スプレッドシート名 | LW／作業日報_全従業員用 |
| 対象シート | 部署マスタ、作業員マスタ |

### E-2. 同期方式

1. Apps Scriptで同期元を開いて読み取り
2. DB側の `DeptMaster` / `WorkerMaster` を**全件置換**
3. `SyncLog` に結果記録（日時、件数、成功/失敗、エラー）

### E-3. 同期タイミング

| タイミング | 方法 |
|------------|------|
| 定期 | 時間主導トリガー（例：毎日 06:00） |
| 手動 | 管理者用「同期」ボタン（任意、後回し可） |

## F. サーバ/API（Apps Script）

### F-1. 関数（UIから呼ぶ）

| 関数名 | 説明 | 返却 |
|--------|------|------|
| `getInit(date)` | 初期データ取得 | 車両一覧、指定日の予約、部署一覧 |
| `getDay(date)` | 指定日の予約一覧（軽量） | 予約リスト |
| `getWorkersByDept(dept_name)` | 部署の作業員取得 | 作業員リスト |
| `createReservation(payload)` | 予約作成 | 成功/エラー |
| `updateReservation(reservation_id, payload)` | 予約更新（v1後回し可） | 成功/エラー |
| `cancelReservation(reservation_id)` | 予約キャンセル | 成功/エラー |
| `syncMasters()` | マスタ同期（トリガー用） | 同期結果 |

### F-2. 排他＆競合チェック

保存系（create/cancel/update）は必ず：

1. `LockService.getScriptLock()` で排他
2. 競合チェック → OK なら書込、NG なら CONFLICT を返す

**返却例（競合）：**

```javascript
{
  code: "CONFLICT",
  conflicts: [
    {
      vehicle_id: "V0001",
      date: "2026-01-23",
      slot: "AM",
      existing_dept: "営業部",
      existing_name: "山田太郎",
      existing_time_range: "08:00-13:00"
    }
  ]
}
```

## G. 保存UX（確実性と省力化）

### G-1. v1（最初）

- 操作確定のたびに**即時保存**
- 画面右上は "状態表示" として `保存済み` を出す程度でOK

### G-2. v1.1以降（自動保存）

日別詳細編集画面を導入したら：
- debounce 自動保存（例 2秒）
- `保存中…` → `保存済み`
- ただし最終的な確実性はサーバの競合チェックで担保
