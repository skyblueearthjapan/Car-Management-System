# 車両管理予約システム 設計仕様書（v0.1）

## 概要

本ドキュメントは、社内車両管理予約システムの設計仕様書（たたき台）です。

### 技術スタック
- **スプレッドシート** = DB（データベース）
- **Apps Script** = API（バックエンド）
- **HTML/CSS/JavaScript** = UI（フロントエンド）

---

## 1. ゴールと前提

### ゴール
- 画面上部で **1週間分の日付タブ** を切り替え
- 選択した日付に対して、車両ごとに **予約（登録/取消/変更）** ができる
- 車両は「基本の保有車（メイン表示）」と「たまに借りられる車（右下の枠）」を分けて表示
- 車両は **図形（CSS）** で表現できれば理想、難しければ **Drive画像** を紐付けて表示

### 予約の粒度（デフォルト案）
- **1日単位の予約（終日）**
- ※将来、午前/午後や時間帯スロットに拡張できるようにデータ構造は拡張余地を残す

---

## 2. 画面仕様（UI）

### 2.1 ヘッダー（上部）

| 位置 | 要素 |
|------|------|
| 左 | ロゴ/システム名 |
| 中 | 日付表示（例：2026-01-23（金）） |
| 右 | 1週間タブ（例：1/23〜1/29）、各タブに「予約件数」バッジ表示可能 |

#### 操作ボタン
- **保存済み**（状態表示）
- **前日** / **今日** / **翌日**（週タブとは別の移動手段）

#### 動作
- **初期表示**: 今日を含む週を表示し、今日を選択状態
- **タブクリック**: 選択日付を切り替え → 車両カードの予約状態を再描画
- **前日/翌日**: 日付を1日ずらす。週を跨いだら週タブも自動更新

### 2.2 メインの車両カード（中央）

車両ごとにカード（角丸枠）を表示。

#### カード内の表示項目
- 車両名（例：カローラホワイト、軽トラA、軽トラB、ノア、ハイエース8080、ハイエース5050）
- 予約状態表示（例：空き / 予約あり）
- 予約者（表示権限があれば表示）
- クリックで予約操作

#### クリック時の挙動（モーダル推奨）
| 状態 | 動作 |
|------|------|
| 空き | 「予約作成」モーダル |
| 予約あり | 「詳細（予約者/用途/メモ）」＋「取消」＋（自分or管理者なら）「変更」 |

### 2.3 右下の「たまに借りられる車」枠

- 例：カローラシルバー、CX5 を表示
- この枠に属する車両は管理画面で増減可能
- 表示は小さめカード/ボタン
- 予約ロジックはメイン車両と同じ（ただし "借り物" 区分が付く）

## 3. 予約ルール（業務ロジック）

### 3.1 二重予約の扱い
- 同一車両・同一日付で **同時に1件のみ**
- 競合時（別ユーザーが先に確定）：
  - 保存時にサーバ側で弾く
  - UIに「他のユーザーが先に予約しました。再読み込みしてください」を表示

### 3.2 予約に持たせる情報（最低限）

| 項目 | 必須/任意 |
|------|----------|
| 車両 | 必須 |
| 日付（開始日・終了日）※デフォは同日 | 必須 |
| 予約者（ユーザー） | 必須 |
| 用途 | 任意 |
| 行先/現場 | 任意 |
| メモ | 任意 |
| 作成/更新日時、作成者、更新者 | 自動 |

### 3.3 権限（デフォルト案）

| ロール | 権限 |
|--------|------|
| 一般ユーザー | 自分の予約のみ取消/変更可能 |
| 管理者 | 全予約を取消/変更可能、車両マスタ編集可能 |

## 4. データ設計（スプレッドシート＝DB）

スプレッドシートは「人が見ても保守できる」＋「Apps Scriptで扱いやすい」を両立。

### 4.1 シート構成

1. **Vehicles**（車両マスタ）
2. **Reservations**（予約トランザクション）
3. **Users**（ユーザー/権限）※最初はメールベースでOK
4. **Settings**（表示順、週開始曜日、UI設定など）※任意

### 4.2 Vehicles（車両マスタ）カラム案

| カラム名 | 説明 | 例 |
|----------|------|-----|
| vehicle_id | 固定ID | V0001 |
| name | 表示名 | カローラホワイト |
| category | メインか右下か | owned / borrowable |
| display_order | 表示順（数値） | 1, 2, 3... |
| plate_no | ナンバープレート | 8080 / 5050 |
| image_drive_file_id | Drive画像を使う場合 | (FileID) |
| shape_type | CSS図形を使う場合のタイプ | (任意) |
| active | 有効フラグ | TRUE/FALSE |
| notes | 備考 | - |

> **重要**: `category` と `display_order` がUIの並びと枠分けを安定させる

### 4.3 Reservations（予約）カラム案

| カラム名 | 説明 | 例 |
|----------|------|-----|
| reservation_id | 採番ID | R20260123-001 |
| vehicle_id | 車両ID | V0001 |
| start_date | 開始日 | 2026-01-23 |
| end_date | 終了日（デフォ=start） | 2026-01-23 |
| user_email | 予約者メール | user@example.com |
| user_name | 表示用名前 | 山田太郎 |
| purpose | 用途 | 現場訪問 |
| destination | 行先 | ○○現場 |
| memo | メモ | - |
| status | ステータス | active / cancelled |
| created_at | 作成日時 | 2026-01-20 10:00:00 |
| created_by | 作成者 | user@example.com |
| updated_at | 更新日時 | 2026-01-20 10:00:00 |
| updated_by | 更新者 | user@example.com |

#### 二重予約防止キー（概念）
- `vehicle_id` + `start_date~end_date` の重複を保存時にチェック
- （将来時間帯に拡張するなら `start_datetime/end_datetime` に移行）

### 4.4 Users（権限）

| カラム名 | 説明 | 例 |
|----------|------|-----|
| user_email | メールアドレス | user@example.com |
| user_name | 表示名 | 山田太郎 |
| role | ロール | admin / user |
| active | 有効フラグ | TRUE/FALSE |

> **備考**: Googleアカウントでログインしている前提なら、基本 `Session.getActiveUser().getEmail()` をキーにできる

## 5. バックエンド設計（Apps Script）

### 5.1 構成
- `doGet()`: HTML返却（UI）
- `google.script.run` で Apps Script の関数を呼ぶ（簡単・CORS不要）
- もしくは `doPost()` のJSON API化も可能（将来的な分離を考えるなら）

### 5.2 API（関数）案

| 関数名 | 説明 |
|--------|------|
| `getWeekData(date)` | 指定日を含む週の Vehicles 一覧と、その週の予約一覧を返す |
| `getDayReservations(date)` | 選択日の予約を返す（軽量再描画） |
| `createReservation(payload)` | 予約作成 |
| `updateReservation(reservation_id, payload)` | 予約更新 |
| `cancelReservation(reservation_id)` | 予約キャンセル |
| `getMe()` | ユーザー情報/role取得 |

### 5.3 競合対策
- `LockService.getScriptLock()` で保存処理を排他
- 保存直前に「同一車両・対象日付（範囲）」に active 予約がないか再チェック

## 6. Drive画像連携（車両画像を使う場合）

### 最低限のやり方
- `Vehicles.image_drive_file_id` に画像File IDを保存
- 画像表示は：
  - Apps Script側で `DriveApp.getFileById(id)` → Blob → Base64化して返す（小規模ならOK）
  - もしくは 共有設定を「リンクを知っている全員が閲覧可」にして、直接埋め込み（運用は楽）

> **推奨**: まずは **画像なし（文字＋枠）でMVP** → 後から画像を足すのが安全

## 7. MVP範囲（最初のリリース）

### MVP（Phase 1）
- 週タブ切替
- 車両カード表示（owned / borrowable の2枠）
- 日付×車両の予約：作成/取消
- 二重予約防止
- 管理者/一般の最低限権限

### 次フェーズ（Phase 2以降）
- 予約の変更
- 複数日予約
- 用途テンプレート
- 通知（メール/LINE WORKS）
- ログ閲覧
- 車両追加UI
