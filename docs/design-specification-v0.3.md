# 車両管理予約システム 設計仕様書（v0.3）

## 概要

v0.1からの主な変更点：
- **予約は複数日＋日ごとのスロット（終日/午前/午後）** を基本に
- **時間指定は"詳細設定（深い階層）"** で日別に持てる構造
- **予約者の部署＋氏名は表示**（既存の「部署マスタ」「作業員マスタ」を自動同期して使う）
- **車のUIはまずCSS/SVGで"かわいく識別しやすい"記号化** を狙い、ダメならDrive画像に切替

---

## 1. 予約仕様 v0.3（複数日＋スロット＋任意の時間指定）

### 1-1. 基本モデル（必須）

- 予約は **期間（start_date〜end_date）** を持つ
- 期間内の各日に対して、**予約スロット**を持つ：
  - **FULL**（終日）
  - **AM**（午前）
  - **PM**（午後）

### 1-2. 時間指定（任意・深い階層）

- "時間指定あり"の場合は **日ごとに start_time / end_time** を持てる
- 位置づけは「スロットの下位詳細」
- 例：AM の中で 09:30-11:00 のように切る
- UIは深くしてOKなので、**通常はスロットだけで予約し、必要時だけ詳細を開く**

### 1-3. 競合（重複）ルール

同一車両・同一日付での競合は**スロット単位で判定**：

| パターン | 競合判定 |
|----------|----------|
| FULL vs AM | **競合する** |
| FULL vs PM | **競合する** |
| AM vs PM | **競合しない** |
| 時間指定あり | 時間帯の重なりで判定 |

> **注意**: FULL は常にその日を占有

## 2. データ設計（スプレッドシートDB）— "ヘッダ＋明細"で拡張可能に

複数日＋日別スロット＋任意時間指定を綺麗に扱うため、**予約は2テーブルに分ける**。

### 2-1. Reservations（予約ヘッダ）

| カラム名 | 説明 | 例 |
|----------|------|-----|
| reservation_id | 採番ID | R20260123-001 |
| vehicle_id | 車両ID | V0001 |
| start_date | 開始日 | 2026-01-23 |
| end_date | 終了日 | 2026-01-25 |
| worker_code | 作業員コード | W001 |
| dept_name | 部署名（表示用キャッシュ） | 営業部 |
| worker_name | 氏名（表示用キャッシュ） | 山田太郎 |
| purpose | 用途 | 現場訪問 |
| destination | 行先 | ○○現場 |
| memo | メモ | - |
| status | ステータス | active / cancelled |
| created_at | 作成日時 | 2026-01-20 10:00:00 |
| created_by | 作成者 | user@example.com |
| updated_at | 更新日時 | 2026-01-20 10:00:00 |
| updated_by | 更新者 | user@example.com |

### 2-2. ReservationDays（予約明細：日別）

| カラム名 | 説明 | 例 |
|----------|------|-----|
| reservation_id | 予約ID（FK） | R20260123-001 |
| date | 日付 | 2026-01-23 |
| slot | スロット | FULL / AM / PM |
| start_time | 開始時刻（任意） | 09:30 |
| end_time | 終了時刻（任意） | 11:00 |

> **メリット**: 「複数日を一括で作って、必要な日だけ時間指定」を自然に表現できる

## 3. 予約者の「部署＋氏名」を表示するための"マスタ同期"仕様

### 同期元スプレッドシート

| 項目 | 値 |
|------|-----|
| ID | `1iu5HoaknlW1W1HheeYv0jqcRq-aY0SyEE2seQd2pHkQ` |
| 名前 | LW／作業日報_全従業員用 |
| 対象シート | 部署マスタ、作業員マスタ |

### 3-1. 同期先（WEBアプリDB側）に用意するシート

| シート名 | 用途 |
|----------|------|
| DeptMaster | 部署マスタ（同期結果） |
| WorkerMaster | 作業員マスタ（同期結果） |
| SyncLog | 同期日時・件数・エラーログ |

#### カラム構成（元シートに準拠）

**DeptMaster:**
- 部署

**WorkerMaster:**
- 作業員コード
- 氏名
- 部署
- 担当業務

### 3-2. 同期方式

- Apps Scriptで**元スプレッドシートをID指定で開いて読み取り**
- 原則は**全件コピー同期**（件数が数千程度なら余裕）

#### 同期頻度
- **毎朝/毎晩の定期同期**（時間主導トリガー）
- UI側に**「マスタ再同期」ボタン**（管理者のみ）で手動同期

#### 同期処理フロー
1. 元の 部署マスタ/作業員マスタ を読み取る
2. DB側の DeptMaster/WorkerMaster を **丸ごと置換**（ヘッダ維持）
3. SyncLog に結果記録

> **方針**: 増分同期（差分）も可能だが、まずは全件置換の方がバグりにくい。重くなったら差分に変更。

### 3-3. "ログインユーザー"を作業員に紐づける問題

作業員マスタにメールアドレス列が無いため、Webアプリのログイン（Googleアカウント）と作業員コードの紐付けが必要。

#### 推奨案：UserMapシート

| カラム名 | 説明 | 例 |
|----------|------|-----|
| user_email | Googleアカウントメール | user@example.com |
| worker_code | 作業員コード | W001 |
| role | ロール | admin / user |

#### 動作フロー
- **初回ログイン時**: UserMapに自分のメールが無ければ「作業員コードを選ぶ/入力する」画面を出す（1回だけ）
- **以後**: UserMapから自動解決

## 4. UI動線（"階層深くてよい"前提の操作設計）

予約作成モーダルを段階化すると、**普段は速く・必要時だけ深く**できる。

### ステップ案

```
┌─────────────────────────────────────────────────────────────┐
│ Step 1: 期間選択                                            │
│   開始日〜終了日を選択                                        │
├─────────────────────────────────────────────────────────────┤
│ Step 2: スロット選択（簡易）                                  │
│   ・全日：終日 / 午前 / 午後                                  │
│   ・「平日だけ」「特定日だけ除外」など（将来拡張）              │
├─────────────────────────────────────────────────────────────┤
│ Step 3: 詳細（任意）- 日別編集                               │
│   ・カレンダー/一覧で各日を表示し、slot変更                   │
│   ・「時間指定」をONにした日だけ start_time/end_time 入力     │
│   （深い階層）                                               │
├─────────────────────────────────────────────────────────────┤
│ Step 4: 確認→保存                                           │
│   ・保存時にサーバ側で競合チェック                            │
└─────────────────────────────────────────────────────────────┘
```

## 5. 車両UI（形状を"かわいく"＝現実的な落とし所）

### 課題
車種名（カローラ/ノア/ハイエース等）から実車に近いシルエットを誰でも一目で…は、純HTML/CSSだけで"確実に"やるのは難易度高め。

### 5-1. まず狙う：カテゴリ別アイコン（CSS/SVG）

車種を分類し、**かわいい統一テイストのSVG**で表現（色やナンバーで差別化）

| 車両 | カテゴリ | 表示 |
|------|----------|------|
| カローラホワイト | セダン | セダンアイコン |
| カローラシルバー | セダン | セダンアイコン |
| ノア | ミニバン | ミニバンアイコン |
| ハイエース8080 | バン | バンアイコン（8080を大きく表示） |
| ハイエース5050 | バン | バンアイコン（5050を大きく表示） |
| 軽トラA | 軽トラック | 軽トラアイコン（Aを表示） |
| 軽トラB | 軽トラック | 軽トラアイコン（Bを表示） |
| CX5 | SUV | SUVアイコン |

> **メリット**: "見た目の完成度"と"保守性"のバランスが良い

### 5-2. ダメなら：Drive画像に切替（すぐ逃げられる設計）

- `Vehicles.image_drive_file_id` を持たせて、画像表示に切替可能にしておく
- 「UIで作れるなら画像不要」方針に沿いつつ、保険を残す
